# S0-09｜FreeRTOS 任务与调度设计 V0.1（评审稿）
2026-11-26。基于 R4 F01–F27、架构 V0.3 与 S0-08。Arduino-ESP32 + PlatformIO 保持不变。以下数字均为初始实验配置，不是已锁定参数或实时性实测结果。S0-06、最终网表及授权仍未闭环。

## 任务模型
六个常驻应用任务、两个按需工作任务；Arduino loopTask、Idle、Wi-Fi/BLE/USB、timer 等 SDK 任务另计。Core 0 倾向通信后台，Core 1 倾向硬件与 UI；先核 SDK 实际任务优先级/亲和性、tick、CPU 与内存再调整。两核共享 Flash/cache、内存、总线，绑核不是硬实时隔离。所有优先级按所选 SDK 支持范围验证。

| 应用任务 | 核心倾向 | 初始优先级 | 栈预算（KiB） | 调度及职责 |
|---|---:|---:|---:|---|
| Safety | 1 | 7 | 4 | 紧急通知 + 10ms监督起点；唯一危险输出控制权；功率/通断状态机和失效保护 |
| Internal I2C | 1 | 6 | 4 | 队列、触摸IRQ通知，唯一内部I2C事务所有者；驱动采集/配置 |
| Measurement | 1 | 5 | 4 | 20ms处理目标起点；消化采样快照，滤波、校准、能量积分、电池数据；不直接争用I2C |
| UI | 1 | 4 | 8 | LVGL单一所有者，按下一次定时期限阻塞；输入、页面、动画和状态呈现 |
| Communication | 0 | 4 | 8 | 有界通信事件、解析、鉴权、命令分发、状态推送；不直接操作危险输出 |
| Maintenance | 0 | 2 | 4 | 日志、持久化、诊断、低频统计；按事件与低频周期运行 |
| Instrument Worker | 1 | 5 | 6 | 按需，外部I2C、ADC连续采样处理、LEDC/PCNT、UART工具等经资源申请；长操作分片/限时 |
| OTA Worker | 0 | 3 | 8 | 按需，升级写入、签名校验和升级状态；统一Flash写入所有权 |

常驻栈预算32KiB，全部46KiB，不含 TCB、队列、SDK 任务、显示、网络等。ESP-IDF FreeRTOS 创建任务栈参数以字节为单位，仍核所选 SDK API；测高水位、实际栈分配、堆碎片及最小余量。不能把 PSRAM 当作所有任务栈或 DMA 缓冲的通用替代。按需任务可预创建阻塞或安全创建/退出，经测量选定；停止前归还资源、结束 DMA/回调、确认无待处理引用，不强制删除持锁任务。任务启动分阶段检查返回值，失败则禁止危险输出并降级。Arduino loop 不忙等，确认实际看门狗和任务职责。

## 数据与控制路径
UI/通信 -> 有界命令队列 -> Safety（危险输出）或对应服务 -> HAL -> I2C 所有者/外设所有者 -> 有效性、时间戳、命令ID和状态快照 -> UI/通信。独立安全关闭通知不与普通遥测共用可能塞满的队列；硬件保护及默认关仍为第一层，软件响应不是硬件过流保护。Safety 不持锁等待 I2C，使用异步请求/结果与超时，禁止 I2C 反向等待 Safety，避免高优先级忙等导致 I2C 无法运行。关断路径应尽可能独立于 I2C，具体由真实电路验证，无法证明时不得宣称失效安全。调压、启用、故障清除均由同一状态机序列化，故障或数据过期时按风险关闭/禁止开启，真实输入模式未确认时禁止危险输出。电压表带电或状态未知时禁用通断激励，不以滤波后的显示值代替保护判据。

内部 I2C 拥有驱动及事务队列，安全相关请求优先，但不能中断正在进行的事务，需限制单次超时、重试及恢复时长，调度触摸以防饥饿；总线故障发布失效状态，不无限重试。触摸 IRQ 只做合规的 ISR 通知，不操作 Wire/LVGL。实际采样频率由 INA226/TLA2528 转换时间、总线预算及风险分析决定；20ms是数据处理起点，不保证新硬件采样。电池充电状态不可虚构，CHG_PG/STAT 当前未接主控。示波器独立 ADC/DMA 缓冲与采集节奏，不用20ms测量任务轮询代替。F01–F05 对应独立主控/USB HUB，不占用本表应用任务；F12–F14、F27 等功能仍须实际接口证明。

## 通信与过载原则
任务通知用于唤醒/故障信号，队列用于有界命令和结果，事件组用于生命周期条件，互斥用于短临界资源且不跨 I/O/回调等待。状态快照用锁短拷贝或正确同步双缓冲，不能无保护共享可变对象；事件组不是数据队列。遥测与波形可按策略合并/降采样/丢弃并统计；控制请求队列满返回 BUSY，不静默丢弃，不无限阻塞。紧急关闭走独立锁存/通知通路，不被普通请求覆盖。跨核 ISR 使用匹配的 FromISR API。固定周期用 vTaskDelayUntil 或适配定时机制，实际 tick 精度待查；LVGL、I2C 与 SDK 调用不可在中断内执行。

## OTA 与系统模式
升级开始前由 Safety 确认输出及通断激励关闭；暂停仪器采集并释放资源，Maintenance 暂停普通 Flash 写入，OTA 唯一写入所有者。通信与必要 UI/安全监控继续，以可运行的低负载模式处理；Flash/cache 停顿可能影响两核，须验证，不依靠软件调度保障输出安全。升级期间拒绝危险操作，签名/完整性校验后激活备用槽；失败或重启后保持关闭，不自动恢复。启动健康检查后才确认新固件，保留 USB 恢复。休眠流程类似受控暂停、唤醒重建资源；具体允许并发功能、超时与电源状态待后续设计。

## 验证要求
记录每任务栈高水位、CPU运行时间、队列峰值、I2C最大阻塞/故障恢复、UI帧/输入延迟、通信丢包与命令超时、看门狗、Flash写入并发及最小内部堆。看门狗喂养与任务真实进展绑定，不用统一盲喂掩盖死锁。模拟 NACK/总线卡死、队列满、测量过期、网络洪峰、任务创建失败、OTA断连/失败与重复启动；真实硬件测试另列。普通任务周期不能当保护响应保证；验收阈值需根据风险和实测锁定。S1未启动，未生成代码、未编译或上板。下一步硬件资源所有权与冲突表；最终引脚以最新网表为准。
