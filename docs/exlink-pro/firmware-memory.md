## Flash候选
采用方屏原始分区表的容量与偏移作为构建验证起点：
| 分区 | 偏移 | 大小 |
|---|---|---|
| nvs | 0x9000 | 0x5000 |
| otadata | 0xe000 | 0x2000 |
| phy_init | 0x10000 | 0x1000 |
| ota_0 | 0x20000 | 0x400000 |
| ota_1 | 0x420000 | 0x400000 |
| assets_a | 0x820000 | 0x380000 |
| assets_b | 0xba0000 | 0x380000 |
| coredump | 0xf20000 | 0x10000 |
末尾0xf30000至0x1000000留832KiB未分配；前部有对齐空隙，不能将空隙任意占用。实际 bootloader、签名后镜像、NVS、资源包、core dump、日志及分区对齐须验证；不保证64KiB core dump够用，不增加未经确认的分区。固件及资源A/B版本、兼容性和完整性一致性应在激活前校验，断电/回滚保留可用组合；固件内保留基础恢复UI。普通OTA不修改分区表；USB恢复路径独立验证。
## SRAM与PSRAM
参考方屏32/16/8行自适应内部单缓冲，RGB565为30/15/7.5KiB；实际DMA能力、异步刷新和CO5300传输约束须验证，后续只有实测支持才调整双缓冲。8MiB PSRAM按需分配图像、动画、历史波形及非实时大型缓冲；不固定原提案各模块额度，不把PSRAM当通用DMA/任务栈。内部RAM优先安全、实时、栈及DMA，预留安全内存。监控最小内部堆、最大连续块、PSRAM、栈高水位、OOM及分配失败；缓存降级、动画降帧、历史缩减、拒绝新增功能、安全降级；不得因装饰或网络负载影响安全。详细诊断只在设置→系统诊断。
