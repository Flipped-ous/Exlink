## 统一升级流程
Wi-Fi HTTP 文件上传为候选，BLE 参考 GATT 二进制分包；共享传输无关接收器、事务所有权、状态和唯一 Flash 写入执行上下文，网络回调仅有界提交，不直接写Flash。参考原生 esp_ota_* 优先验证；Arduino Update.h 为既有备选，不并行使用两个写入器。应用与资源分别使用对应 sink，不重复业务。
1. 检查元数据、目标硬件/类型/版本、容量、身份/授权及发布者签名；完整载荷尚未收到时不能声称已验证其实际摘要。
2. 用户确认后锁定升级事务，取消旧控制请求，经 Safety 确认危险输出关闭、暂停冲突工具与普通配置写入，阻止休眠；未安全停止不得开始。
3. 流式写入非当前运行/活动分区，有限缓冲与流控，进度以接收器确认的有效写入偏移为准；不重复整包缓存。
4. END 验证完整长度、实际 SHA-256、签名对应的摘要、镜像/资源格式及硬件版本兼容，任何错误禁止激活。
5. ACTIVATE 与 END 分离；固件选择启动槽后重启，资源验证后切换记录并刷新缓存；保持可回退兼容组合及内置恢复界面。
6. 新固件在健康检查通过后才标记有效，失败请求回滚。延迟 Arduino Core 自动确认，实际 bootloader/SDK 支持、旧有效槽存在及配置迁移兼容必须验证。不能把重启/传完/收到 ACTIVATE ACK 当成成功；重连查询实际版本及健康状态。健康检查标准按实际板卡及关键服务定义，不因可选功能失效无限重启，不绕过必要安全条件。
失败、取消、超时、升级重启均不自动恢复已关闭危险输出。S0-13 安全优先。

## 断连与异常
有限重连和同一已认证事务续传，以设备确认偏移为准；拒绝过期会话、越界、乱序、错误CRC和未知事务；重复已确认数据不得重复写入，ACTIVATE 未确认时查询实际状态而非盲目重发。首版不强制跨设备掉电、进程丢失续传或 Wi-Fi/BLE 无缝接力；不同通道不能并发启动升级。固件写入未完成时保留当前有效槽；断电时激活记录/otadata、资源与配置一致性必须实测，不做绝对恢复保证。新镜像失败时仅在回滚配置及另一有效镜像满足时回滚；两槽无法启动或分区迁移时 USB 有线恢复，实际接口和恢复包须验证。首次部署无旧有效镜像，不承诺自动回滚。
