## 职责与通信机制
本机LVGL、EXLINK Mobile及Studio共用设备业务服务。Command Dispatcher负责可信来源识别、鉴权、参数校验、命令分发，不作为全局串行硬件执行任务；对应服务拥有业务状态和控制顺序，HAL执行硬件操作。采用轻量FreeRTOS队列、任务通知、同步状态快照及独立有界缓冲，不引入复杂消息中间件。
| 类型 | 机制 | 用途 |
|---|---|---|
| Command | 有界Queue | 设置电压、启动PWM等 |
| Result | 有界Queue | 请求关联的终态结果 |
| Event | Queue/Notify | 故障、连接及状态变化 |
| State | 同步快照 | 设备权威状态 |
| Stream | 独立Ring Buffer/采样缓冲 | 示波器、串口等 |
Safety独立监控、锁存与紧急关断，不依赖普通队列、日志或界面。普通事件丢失后可查询权威状态；不以任务通知代替需要保留完整载荷的队列，不把所有数据逐样本放进公共事件队列。

## 命令定义与生命周期
内部候选结构（不是最终API或线上格式）：
```cpp
struct CommandHeader {
    uint32_t id;
    CommandSource source;
    CommandType type;
    uint64_t timestamp_ms;
};
struct SetVoltageCommand {
    CommandHeader header;
    int32_t target_mv;
};
```
来源包括本机UI、手机、电脑及系统内部。身份、会话及有效性由可信入口绑定，不信任客户端自报身份或时间；请求ID以来源/会话为范围去重。内部类型化参数不直接按C++内存结构序列化到Wi-Fi/BLE。命令提交→校验权限、参数、安全及结果信用→对应服务排队→HAL/唯一总线所有者执行→更新权威状态→关联终态结果及多端状态同步。区分已接受、配置写入/回读和实际物理验证。例：设定5000mV不等于开启输出；OFF时修改目标仍保持OFF。超时不等于未执行，查询状态再决定是否重试，不盲重放危险操作。
接受前预留终态结果容量，成功、失败、取消等路径正确回收信用，考虑消费者断连及过期结果；执行结果不静默丢弃。明确队列满、重复ID、超时、旧命令和故障状态，沿用S0-12错误语义，最终线上编码待S1-09。

## 多端与安全
允许授权多端同时读取；同一功能修改由对应服务串行处理，资源冲突拒绝或按已确认策略处理；不采用全局单客户端强制互斥。设备为最终权威。本机/授权端关闭输出优先，Safety真实故障独立紧急关断；关闭、故障及维护时使过期的开启命令/迟到结果失效，不能重新开启危险输出。OTA期间拒绝普通危险操作。正常远端断连本身不关闭正常输出，取消失效未执行请求，重连重新同步，不重放危险命令；本机及安全服务持续运行。远端通断仍按S0-14首版只读。安全和实际关断确认遵守S0-13，不新增保护阈值。

## 状态管理
按服务管理权威状态，对应业务服务为更新者，其他模块通过短锁同步拷贝或正确同步的快照读取；避免巨型可变全局结构或跨I/O持锁。PowerState候选字段：target_mv、voltage_mv、current_ua、power_uw、output_enabled、valid、fault、revision、sampled_ms。目标、实际测量、有效性和输出状态分开；有符号物理单位，复位/会话及状态版本用于重同步，失效数据不得冒充实时或零值，关断未确认不能伪装已关。示意数值不代表实测，字段最终类型、有效性细分和线上schema待细化；状态权威与Safety锁存不依赖事件及时送达。
