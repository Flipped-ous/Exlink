## A. 当前有效产品基准（V1.8）

> **用途**：当前有效产品需求、交互和技术边界均集中于本文件；继续阅读同文件的 B「每日修改与定稿日志」及 C「竞品研究」。

## 01. 产品定位（已确认）

- 名称：**EXLINK Studio**；当前产品/UI 设计基准 **V1.8**。
- 核心定位：**Windows 优先、无需 EXLINK PRO 硬件也能使用的通用嵌入式调试助手**。面向 STM32、ESP32、机器人、电机控制、智能车和嵌入式开发者。
- 产品竞争力：**工具多、分类全、快捷使用、数据可靠、低学习成本**。日常调试效率优先，视觉美观但不能牺牲操作。
- 普通用户：打开即能选 COM 口并收发数据；专业用户：多连接、多视图、波形分析、参数调试和轻量自定义。
- 软件与 EXLINK PRO 硬件解耦；专属逻辑分析、电源等能力必须由真实固件/硬件支持，未实现时不得伪装可用。

## 02. 当前主界面架构（已确认 / 设计基准）

1. **左侧窄活动栏**：默认 `串口助手` / `网络调试` / `逻辑分析` / `图像调试` / `工具箱`；`设置`置底。工具箱内的功能支持搜索、固定到导航、取消固定。导航选择**工具类别**。
2. **顶部真实标签栏**：用于**已打开的工具/调试视图实例**，可重命名、切换、关闭、新建；不要只当标题使用。支持同一 COM3 的「速度环 / 姿态 / 电机」等多个标签。标签切换**不等于**重新打开端口。
3. **主工作区**：根据任务显示日志、波形、图像或数字时序；不以固定三栏作为所有页面的统一模板。
4. **波形区域**：大波形图为主；**通道位于图下方**，采用逐飞助手式紧凑开关/图例，默认只显示颜色、名称、当前或游标数值、显示状态；高级属性按需展开。波形缩放使用鼠标滚轮：普通滚轮控制横轴时间缩放，`Ctrl + 滚轮` 控制纵轴幅度缩放；鼠标中键拖动平移波形，双击恢复默认视图。
5. **底部日志与发送**：日志可以折叠和调整高度；发送输入高频可达；**不保留无意义的全局底部统计栏/设备状态大条**。工具内部仍可按需显示必要的连接、接收、错误反馈。
6. **AI 入口**：参考 Lissio，顶部按钮呼出**右侧可调整宽度的辅助面板**；AI 不占一级导航，默认隐藏，不能打断采集或擅自写硬件。
7. **响应式规则**：以窗口当前可用宽度和高度（含系统缩放）决定布局；宽窗口可分屏，普通窗口主视图优先，紧凑窗口折叠通道/日志/AI 等辅助内容；不强制三栏。

## 04. 历史参考与数据原则

- **同一个 COM3 可以有多个不同调试视图**；每个视图独立设置字段、过滤、颜色、单位、布局，但共享一个实际物理连接和底层数据流。
- **同一数据源多次测试**：允许把片段命名成「速度环 Kp=12」等并保存，便于新旧曲线叠加；对比优先设计在当前视图内部，不应为了历史对比创建独立常驻一级工具。
- 历史片段应记录来源、时间戳基准、通道单位、必要的调试条件；禁止把不同采样时间/单位的数据未经处理直接对齐并作为工程结论。
- 用户曾明确拒绝**“统一调试会话中心 / 项目中心”**。**轻量参考片段 ≠ 重新引入重型实验数据库**。
- `保存参考` 的交互形式（工具栏下拉、轻量列表、叠加/分屏）仍属**候选交互细节**，应在实际原型验收时最终确认。

## 05. 工具箱与导航边界

- **默认一级导航**：串口助手、网络调试、逻辑分析、图像调试、工具箱、设置。
- **不在默认导航**：AI（顶部/右侧面板）、电源调试（工具箱）、波形（串口工具内视图）。
- **工具箱候选分类**：通信/协议、信号与控制、测量与电源、开发辅助、数据处理。
- **工具箱内的设备相关工具**：可调电源、直流电压表、断电通断、I²C 扫描、PWM 输出、频率计、低速模拟采样、固件维护、调试器辅助等；与 EXLINK PRO 的物理接口、固件映射和安全校验相关。
- **EXLINK PRO 不等于默认必备设备**；不建“设备中心”作为用户必须经过的流程。

## 06. 当前视觉与全软件 UI 基准（2026-11-20 最新确认）

> **DEC-20261120-001：用户明确确认「专业混合风格（浅灰工具栏 + 深色波形区）」适用于 EXLINK Studio **整个软件**，而非单独的波形页面。**本节替代旧的「全深石墨灰 + 紫色主调」整体视觉基准**；功能布局仍沿用 V1.8 已确认需求。软件整体具体界面原型为新方案展示稿，**尚未得到最终视觉验收**。

### 06.1 已确认的全局设计方向

- **产品风格**：专用工科/嵌入式调试桌面工具，强调信息密度、坐标/单位/数据准确性、工具可发现性；避免看板网页、浮夸光效、装饰性数值卡。
- **工具外壳**：浅灰色的左侧活动栏、顶部真实标签栏、连接/参数工具栏、工具箱与设置区域，控件紧凑、细分隔线、适当留白。
- **数据画布**：波形图、逻辑时序、图像/HEX 等测量与数据读取区域采用深色、高对比度的不透明底色；数据通道、坐标轴、单位和游标可读。
- **色彩语义**：中性灰主导，少量蓝绿用于主要选中态；警告、故障、正常状态使用具备明确语义的颜色，不用紫色装饰所有主按钮。
- **应用范围**：串口助手（日志/波形/在线调参）、网络调试、逻辑分析、图像调试、工具箱、设置、右侧 AI 辅助、窗口紧凑态和 EXLINK PRO 相关工具统一遵循本风格。
- **功能架构不变**：无首页/设备中心/会话中心/独立波形一级页；左侧分类活动栏、顶部多标签、波形下方紧凑通道条、AI 右侧按需展开、滚轮缩放操作继续有效。

## 08. 技术与安全边界

- 技术栈当前建议：**Tauri 2 + React + TypeScript + Rust**；属于推荐实现路径，尚非经过代码验证的最终选型。
- 架构候选：连接管理 `Connection` → 统一解析/字段缓存 `Data Stream` → 多调试视图 `View` → 可选历史片段 `Reference`。
- 接收不受图表刷新阻塞；图表降采样不改变导出的原始数据；暂停显示与停止记录/断开连接行为分开。
- 在线修改 PID 等控制参数必须匹配目标 MCU 协议与确认机制；AI 只读优先，不能无批准自动向电机或其他硬件发送控制指令。
- 特定电源、测量、逻辑分析功能只能在兼容 EXLINK PRO 固件、硬件及接线验证后启用；硬件安全互锁优先于 PC UI。
- 竞品参考：逐飞助手、龙邱助手、Lissio、VOFA+、Serial Studio、PlotJuggler、Saleae Logic 2、FluentHMI Studio、Fluent Serial Assistant 等；竞品的代码许可需单独评估，不直接复制。

### DEC-20261118-001｜确认波形鼠标缩放与浏览交互

- **用户确认过程**：用户先明确提出波形放大操作应使用鼠标滚轮；在解释 `Ctrl + 滚轮` 的含义后，用户回复“可以”，确认该交互方案。
- **最终确认内容**：
  1. 普通鼠标滚轮向上/向下：放大/缩小波形横轴（时间轴）。
  2. 按住 `Ctrl` 同时滚动滚轮：放大/缩小波形纵轴（数值幅度/显示范围）。
  3. 鼠标中键按住并拖动：平移波形视图，查看其他时间区间。
  4. 双击波形区域：恢复默认缩放视图。
- **解释**：横轴代表时间，纵轴代表通道数值；纵轴缩放只改变显示范围，不修改采样值或原始记录。
- **设计原则**：缩放、平移和复位仅影响视图，不得停止后台采集或改变原始数据；实时采集与历史数据浏览应保持分离。
- **尚待原型验证的细节**：滚轮缩放步进、缩放中心是否锚定鼠标指针、触控板手势适配、不同通道单位/独立纵轴时的具体行为。上述细节不因本次确认而自动定稿。
- **状态**：波形鼠标交互方向 **已确认**；实现和手感 **待原型验证**。
- **影响范围**：串口助手内嵌波形、多通道波形、历史参考曲线对比。

## 维护与版本规则

1. **一日一条主日志**：同一天继续讨论时向该日期章节追加 DEC / CHG / IDEA，不为同一天重复创建多个日期标题。
2. **即时记录 + 每日定稿**：每次用户确认就记录；当日结束以一份快照说明“今天以哪个方案为准”。如果一天有多版，以最后一项用户明确确认的版本为准。
3. **任何变更不可抹去**：撤销也以新 CHG 编号追记，写清旧决定被谁替代、为何替代。
4. **单文件内基准同步**：只有 `已确认` 的内容才能上升到本文件 A「当前有效产品基准」；`候选` 不成为必须开发的需求。
5. **产品版本 ≠ 文档版本**：EXLINK Studio V1.8 是产品视觉/交互设计基准；R1/R2 是 Markdown 记录文件修订。
6. **软件专用**：此日志只管理 EXLINK Studio，不混入 EXLINK PRO PCB/固件的设计日志。对接硬件时只记录依赖及验收门槛。
7. **持续更新条件**：需在后续对话中有最新讨论内容，且可访问此唯一 Markdown 文件；不会在无对话时自动编辑用户本地文件。
8. **唯一文件约束**：以后不再额外新建「需求」「日志」「研究」等独立项目记忆文件，只在本文件内添加标题章节。

- **已重新核对的原始案例**：ArduPilot 开发者 Georacer 2024-08-12 的《Log inspection with PlotJuggler》明确称赞流畅缩放、跨图同步游标、布局复用，同时指出不同时间轴需要重采样；Saleae 论坛《I2C decoding concern》用户在应用 glitch filter 后肯定数字/模拟结合及快速回复；Serial Studio GitHub #289 确有用户称赞但同帖主要报告崩溃，属于「好评+问题」混合样本。
- **正面信号（可用于设计评审，尚非新需求定稿）**：①快速上手/基础串口零工程；②布局及通道配置自动持久化；③跨图时间轴和游标联动；④数据与日志使用中保持流畅；⑤清晰的错误诊断和可复现的修复反馈；⑥体量与分发门槛低。
- **关键限定与修正**：
  1. 少数具名好评不能统计推断「性能是所有用户第一优先」或比较竞品实际质量；报告按「好评密度」分类仅说明本轮检索到的公开样本。
  2. PlotJuggler 的**已带时间戳的日志多图同步**，不等于裸串口字节流天然具备相同精确采样时间；应区分 MCU 采样时间、主机接收时间、界面绘制时间，跨源同步需验证。
  3. VOFA+ `JustFloat` 的已知格式可推断通道数，不表示任意 CSV/二进制帧都能无配置且无歧义自动识别；识别失败需保留原始数据与诊断信息。
  4. 正面报告提出的「拖滑块立即向电机下发」不可照搬；按既有 R-008，参数修改默认**手动应用+设备确认**，自动发送必须明确启用且限速防冲突。
  5. 「Windows 单文件、无运行库」是候选分发目标，并不是 Tauri 2 技术栈必然保证；WebView2、签名、安装器和绿色发行都需实机测试。免费/开源/无授权也不能仅由零星用户原话直接定稿为商业模式。
  6. 演示数据必须显著标注；允许保存/导出与否属待讨论交互选项，不宜从竞品报告直接生成硬禁令。
- **建议的后续测试/产品指标（全部候选）**：从连接到首次可读日志/首次波形的操作步骤；视图跨会话自动恢复；多图缩放/联动游标响应；日常与长时采集内存界限；COM 异常释放与诊断；参数写入确认结果；用户能否自己导出诊断包。
- **范围与决策状态**：本次只是阅读、核实和评审上传报告，**用户未逐项确认新增功能**；V1.8 的已确认范围、已取消项和单文件维护规则维持不变。用户确认后再建立 DEC / CHG 记录。

## 2026-11-20｜UI 视觉评审与修改记录

### CHG-20261120-001｜当前 UI 演示稿未达到工程实用软件质感

- **用户原意**：“不对不对，我觉的现在的ui有点丑啊，不是专用的工科实用软件”。
- **修改前**：V1.8 深石墨灰、紫色突出、带数值卡片与示意曲线的演示风格，曾用作波形区域视觉说明。
- **修改后**：对**当前演示稿的视觉呈现**停止视为已获认可，列入**待重新设计与评审**；不把示意曲线图当成已定稿 UI。
- **原因**：用户明确指出专业属性、实用感和视觉品质不足；需要以工程调试的实际操作路径与信息层级重新设计，而不是只换色。
- **影响范围**：串口日志、波形监视、工具栏、参数面板、数据状态及整体视觉语言。
- **状态**：**用户反馈已记录，当前演示稿视觉不通过**；未来视觉方案**未最终确认**。
- **不变部分**：此前已确认的工作区信息架构、波形下方通道栏、同 COM 多视图、滚轮缩放交互等不因本次视觉反馈自动取消。

### IDEA-20261120-001｜专业工程工具式 UI 重设计（候选）

- **候选方向**：弱化装饰性卡片、泛紫色强调和虚构仪表盘观感；提高曲线有效面积、坐标轴和单位精度、工具栏紧凑度；采用细分隔、清晰层级、可折叠参数与日志、浅色工具区/深色绘图区或统一中性深色等备选主题。
- **波形规范建议**：原始时序决定曲线形态；线条抗锯齿但不假平滑；带明确单位/刻度、数据缺口、采样状态与时间游标；演示数据必须显著说明。
- **状态**：**候选、等待评审**，用户尚未确认最终配色和新布局。

### DEC-20261120-001｜全软件采用专业混合 UI 风格（用户明确确认）

- **用户原话**：「EXLINK Studio UI 重新设计方向确认：选择专业混合风格（浅灰工具栏+深色波形区）。请以工程师实用工具为目标重新设计具体界面，并更新唯一项目记忆。」随后追加：「还有一点这个是软件整体的方案」。
- **正式结论**：混合风格是整个 EXLINK Studio 的统一界面语言，包含串口、网络、逻辑分析、图像调试、工具箱、设置、AI 辅助及相关硬件工具，而不仅是波形页面。
- **已确认的风格边界**：浅灰导航、工具栏和参数区；深色专业数据绘图/浏览区域；工程软件式紧凑布局、清晰控件与数据刻度，避免网页式大卡片和夸张科技光效。
- **替代关系**：覆盖 A.06 旧版「整体深石墨灰+紫色主视觉」基准；不自动取消原已确认的功能架构和波形鼠标交互。
- **状态**：**已确认（全软件风格方向）**；具体设计稿、像素尺度、色彩值、局部交互仍待用户验收。

### CHG-20261120-002｜全模块 UI 原型制作与范围澄清

- **修改前**：只围绕串口波形讨论「浅灰工具条+深色绘图区」的单页示例。
- **修改后**：全局框架和每个一级功能模块均需按同一套专业混合风格展示；顶部真实标签、多视图、硬件可用性提示遵循 V1.8 已确认约束。
