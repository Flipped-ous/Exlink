# EXLINK Studio：交互与实现建议

> 定位更新：用户已提供 EXLINK PRO V4.8 硬件主文档，并明确软件优先服务这一款多功能调试器。最新 UI 基准见 [ui-layout-v4.8.md](ui-layout-v4.8.md)。本文的数据处理建议仍可参考；早期通用工具定位及导航建议以新基准为准。

## 依据与边界

本方案基于引用会话当前可读取的 V1.7 汇总和近期修改意见。读取接口未返回早期设计图片或完整历史，因此不评价具体旧图的细节。当前工作区没有应用代码。本次产出为交互设计稿和实施方案，不是已接入硬件的桌面应用。

产品定位保持为独立的嵌入式调试工具，不要求连接 EXLINK 专用硬件。第一阶段以 Windows 为验证目标，跨平台能力留在适配层，逐个平台验收。

## 首要调整

1. **数据连接与展示分开。** 一个标签持有一个连接，标签内可以切换日志、日志加波形、调参。切换视图不会重开串口或清空缓冲。内部可以有会话对象，但不新增“会话中心”页面。
2. **默认允许日志和波形同屏。** 调参也保留原始日志，便于看出命令发出了什么、设备实际回了什么。新建无解析配置的串口先打开日志；已有数值解析配置的连接可恢复混合视图。
3. **层级按使用频率排列。** 连接放顶部，数据在中央，发送在底部，工具相关属性和 AI 按需展开。普通窗口优先只开一个右侧栏；若已有参数草稿，打开助手不能丢失草稿。
4. **保留简短文字导航。** 初次使用能辨认串口、网络等工具；后续可收起成图标。图标统一采用现成线性体系，品牌 Logo 另做，不让标志设计阻塞串口开发。
5. **减少视觉噪声。** 灰阶背景与细分隔线组织区域；强调色用于当前项和主要动作；曲线使用稳定且可区分的颜色与线型。禁止把统计卡片和装饰性大标题放到调试主工作区。
6. **能力由真实协议决定。** 调参、图像、逻辑采样、电源输出属于不同协议与硬件能力，不能因为都是串口传输就视为自动可用。

## 主操作流程

选择端口与配置 → 打开连接 → 接收原始数据 → 选择解析方式 → 日志与曲线联合观察 → 发送指令或编辑参数 → 保存记录。

高级连接项（数据位、校验、停止位、流控）收入展开设置。当前波特率、端口、连接状态保持可见。运行期间改连接配置须明确提示将重连；有未确认写入时阻止直接改配置。

发送区固定在当前连接的底部。快捷指令默认填入输入框，显式发送，避免误触立即执行。HEX 模式校验偶数长度、合法字符及空白分隔；ASCII/UTF-8 模式明确编码及行尾。RX 显示暂停、停止采集、断开连接是三个不同动作。

## 建议技术结构

采用 Tauri 2 + React + TypeScript + Rust。该组合能将桌面界面与串口、文件、解析职责拆开，但包体、内存和吞吐量需要实测，不能只根据框架名字承诺性能。

```text
React 界面
  ├─ 应用外壳 / 连接标签 / 工具导航
  ├─ 连接配置 / 发送区 / 快捷指令
  ├─ 虚拟列表日志 / 波形画布 / 参数编辑
  └─ UI 状态（当前标签、布局、草稿、选区）
                 ↕ 命令 / 批量数据通道
Rust 核心
  ├─ ConnectionManager：串口和网络适配
  ├─ 每连接一个读任务、一个串行写队列
  ├─ 原始字节记录与有界缓冲
  ├─ 分帧 / 校验 / 解码 / 通道映射
  ├─ 参数请求、应答关联、超时与读回核对
  └─ 文件记录、导出、硬件能力适配
```

Tauri commands 负责低频操作，例如枚举端口、连接、断开、发送和读取参数；Channel 承载批量流数据。禁止每收到一个字节或采样点就触发一次界面状态更新。

官方依据：
- https://v2.tauri.app/develop/calling-frontend/ ：Channel 适合流式传输。
- https://github.com/serialport/serialport-rs ：串口枚举及阻塞式读写接口。

serialport-rs 是阻塞接口，读操作放专用线程或受控阻塞任务，设置有限超时，设计退出信号与资源释放；不能直接卡住异步执行器或 UI。采用按连接拥有资源的服务，页面组件只订阅数据；组件卸载不能意外关闭仍被使用的连接。

## 容易返工的细节

### 串口没有天然的数据包边界

一次 read 可能只有半帧，也可能包含多帧。先累计字节并分帧，再解码；文本需要跨块保持 UTF-8 解码状态。先支持换行数值或 CSV，再加入固定长度、帧头长度校验等协议适配。坏帧要能重同步，并保留原始字节追溯。

“任意串口数据自动画波形”不应成为承诺。用户需要选择分隔符、字段及通道映射；预览解析结果后生效。二进制浮点数据必须明确端序和字段布局。

### 数据吞吐与 UI 刷新分开

接收、解析、记录独立进行；前端按帧批量消费，例如先以 30 Hz 为试验起点，最终由实测调整。日志使用虚拟列表、明确内存上限和截断提示。曲线显示按像素桶保留极值，避免简单隔点抽样隐藏尖峰。显示降采样不能改变原始记录。

每连接使用有界队列。若显示消费者落后，可以丢弃旧的显示快照；原始记录队列则应报告溢出，必要时停止记录并显示不完整标记，不能静默丢失还宣称完整。磁盘慢、磁盘满和导出失败必须独立处理。

### 连接状态必须可解释

```text
disconnected → connecting → connected → disconnecting → disconnected
                    ↘ error ← 端口占用、拔出、读写失败
```

端口重新出现不代表可以恢复所有写操作。初版断线后由用户重连；清除定时发送和未完成请求，保留日志。后续如加自动重连，必须重新校验设备身份，不能自动重发可能改变硬件状态的命令。

同一端口的第二次打开应提示“已在另一个标签打开”，允许切到已有标签。全局连接服务负责独占和关闭，而非各页面分别抢占端口。

### 参数草稿不等于设备实际值

状态至少区分：未读取、已读取、已编辑、待应答、已核对、失败、结果未知。设备读值、用户草稿、最后成功写入值分别保存。界面显示参数单位、范围及修改标记。

协议要定义参数 ID、类型、范围、请求关联、应答和读回机制。超时可能是写入成功但应答丢失，所以不能直接断言“未写入”，也不能自动重复危险指令。多参数写入无事务保障时逐项报告结果；“回退”是一次新的写入，必须再次应答核对，不能保证硬件一定恢复。

### AI 后置且由用户选取上下文

第一版不调用 AI。后续只传用户选中的日志或波形区间及必要配置，发送前提供上下文预览。AI 建议生成待发送命令或参数草稿；底层服务仍负责参数校验、连接能力检查及实际写入流程。

## 实施顺序和验收

| 阶段 | 可交付结果 | 核心验收 |
| --- | --- | --- |
| 交互稿 | 日志、混合、调参布局和展开栏 | 窄窗口可用，关键操作明确；不伪装真实连接 |
| 串口闭环 | 端口枚举、配置、收发、HEX、时间戳、原始记录 | 两串口独立收发；端口占用和拔插提示；退出释放端口 |
| 数据可视化 | 换行/CSV 解析、通道映射、波形、暂停与导出 | 拆帧粘帧正确；显示暂停不丢记录；持续数据内存稳定 |
| 协议调参 | 一个真实 MCU 协议适配 | 写入应答、超时未知状态、读回核对、部分失败可解释 |
| 扩展工具 | 网络及图像，之后逻辑分析和硬件工具 | 以实际使用场景和硬件协议逐项验收 |
| AI | 选区分析及命令草稿 | 上下文可预览，核心调试不依赖 AI 服务 |

第一份真实版本只承诺“能稳定连接、看懂数据、可靠发送并保留记录”。每新增工具复用传输和解析基础，不先搭建插件市场或自由拖拽布局系统。

## 本次设计稿可操作范围

可切换日志、混合、调参视图；展开连接设置、工具箱和助手；切换深浅主题；开关曲线；查看 HEX；填入快捷指令；向本地日志追加模拟发送。

波形和日志均为说明布局的示例数据，未做逐采样对齐。保留草稿只保留当前预览内存；不写设备，也不承诺关闭后持久化。网络、逻辑分析与图像入口在稿中禁用。尚未初始化 React/Tauri 工程、打包桌面程序或进行真实设备测试。
